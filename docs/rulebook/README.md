# LOL-GM 공식 규정집 — 사용자 확정 규칙

**규정집 발행본:** v1.0.0 · 2026-11-01 (최초 편찬)  
**성격:** 사용자 승인 게임 규칙의 독립 정본. **게임 코드 구현 여부를 의미하지 않는다.**

이 디렉터리는 기존 `DECISIONS.md`, `DEVELOPMENT.md`, 개별 기획 문서, PR #327과 **독립적으로** 관리한다. 개별 이슈·사용자의 승인 댓글은 근거 기록이고, 이 규정집은 실제 게임에서 지켜야 할 **현행 확정 규칙만** 정리한 것이다. 최초 편찬은 새로운 게임 규칙을 승인하는 일이 아니다.

## 수정하더라도 복잡해지지 않는 관리 방법

1. **한 규칙의 정의는 해당 분야 파일 한 곳에만 둔다.** 다른 장은 고유 규칙 ID를 참조하고 동일 문장을 복사하지 않는다.
2. **고유 ID는 영구 유지한다.** 예: `TRANS-001`. 개정하더라도 ID를 재번호 부여하거나 과거 출처를 지우지 않는다. 한 조항의 뜻이 서로 다른 둘로 나뉘는 경우에만 새로운 ID를 추가하고 관계를 남긴다.
3. **실제 변경이 승인된 경우에만** 해당 분야 파일과 [CHANGELOG.md](CHANGELOG.md)를 함께 고친다. 로그에는 변경 조항, 이전/새 버전, **사용자 확정 근거**, 적용 대상·시즌·효력 시점을 적는다. 단순 오탈자/링크 정정은 의미 변경과 구별한다.
4. 이전 결정·원본 계약·대회 역사·당시 규정 버전은 삭제하지 않는다. **게임 내부 사무국이 차기 시즌 규정을 합법적으로 바꾼 것**은 해당 저장 세계의 `rulesVersion` / `effectiveSeasonId` 이력에 기록한다. **그때마다 이 규정집을 수정하지 않는다.** 이 규정집은 사무국이 따르는 상위 규칙과 정당한 개정 권한을 정한다.
5. 과거 문서·PR/이슈의 제안·개발 TODO·미확정 계수·구현 진행률은 **규정집에 복사하지 않는다**. 출처끼리 충돌하면 더 나중에 명시적으로 승인된 동일 쟁점의 결정을 따르며, 아직 판단할 수 없으면 **임의 확정해 기재하지 않는다**.
6. `main`에 병합되지 않은 편찬 PR은 **공식 반영 완료로 표시하지 않는다**. 문서 편찬·코드 구현·테스트 합격·실제 게임 적용은 서로 별개다.
